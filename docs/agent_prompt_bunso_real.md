# 给接手 agent 的提示词：导入文综真题（省额度版）

你要接手 `Nayukiiii/eju-sprint`（EJU 备考静态站，原生 JS，无构建，用户在中国使用，**禁止外部 CDN**）。用户的额度有限，**每个 token 都要花在刀刃上**。

## 先读这些（只读这些，别的先别读）
1. `docs/bunso_real_import_plan.md` —— 完整方案、分工、数据格式、进度清单。以它为准。
2. `bunso_ocr/*/report.md` —— 用户提交的校对清单。没有这个目录说明用户还没跑脚本：只回复「请先在本机运行 tools/ocr_bunso.py 并提交 bunso_ocr/」，**不要自己去 OCR，不要凭记忆编题**。
3. 要改接口时才读：`mock_bunso.js`（约 300 行）、`build_math_bank.js` 作为生成脚本的样板。**不要通读 `app.js`（3000 行）**，用 `grep -n` 找到要改的函数，再用 Read 的 offset/limit 读那一小段。

## 省额度的硬规矩
- **不要逐页看图。** 先看 `report.md`：只看它标出的疑点（无答案、依赖图表、选项数不是 4、重复题号），其余题抽查 3–5 道即可。每看一张页图都要有明确目的。
- **能用脚本验证的别用眼睛**：写小脚本检查每回题数连续、每题 4 个选项、`a` 在 0–3 内、`a` 与正解表一致、没有空题干。脚本报错再处理错的那几题。
- **一回一回做，做完一回就提交一次。** 不要攒着一次性提交；额度随时可能用完，已提交的才算数。先做用户提交的最近一回，跑通整条链路（核对 → `bank_bunso_real.js` → 模考切换 → 测试），再扩到其他回。
- 中文翻译、解析、易错点放最后做，**不是上线真题的前提**；没时间就留空，`mock_bunso.js` 的日文优先模式没有中文也要能用。
- 不要重新生成已经存在的东西（`bank_math_real.js`、数学模考、仿真卷）；不要「顺便」重构。
- 测试只跑相关的：`node tools/tests/mockb.test.js`（需先 `python3 -m http.server 8765`）、`node tools/check_cn.js`、新增文件的 `node --check`。不要整套反复跑。
- 答案以官方正解表为准，**不要用 LLM 的判断替代**；对不上的题以正解表为准并在 `auditNote` 里记下。看不清的题宁可不收，也不要猜。
- 回复要短：做了什么、没做什么、下一步。不要复述方案文档。

## 要交付的东西（顺序即优先级）
1. `tools/bunso_src/<年份_回>.json` + `tools/build_bunso_bank.js` → `bank_bunso_real.js`（`auditStatus:"verified"`，`source:"YYYY第N回 問X"`），并在 `index.html`、`sw.js`（`ASSETS` + 缓存版本号 +1）接入。
2. `mock_bunso.js` 加「真题（按整回）/ 仿真卷」切换；真题模式整回出卷、按科目出报告、不再写「非真题」。
3. 方案页成绩记录、`app.js` 里的「未核实」统计与核验页文案同步。
4. 补测试，390px 手机宽度截图。

## 收尾
- 每做完一块就更新 `docs/bunso_real_import_plan.md` 末尾的「进度」。
- 额度不够时：提交当前成果，在「进度」里写清楚做到哪、剩什么，然后停下，不要留下半截没提交的改动。
- Git：在指定分支提交并推送；用户没有要求就不要建 PR。
