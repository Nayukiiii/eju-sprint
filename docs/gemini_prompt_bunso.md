# 丢给 Gemini 的提示词（文综真题转写）

用法：每次开一个新对话，**一回一回做**。先把这一回的「题卷 PDF」和「同一回的正解表 PDF」一起上传，再把下面「提示词」整段贴进去发送。输出是 JSON，复制保存成 `bunso_ocr/<年份-回>/draft.json` 提交到仓库。
（我不了解你说的具体型号的细节，提示词按「能直接读 PDF/图片、一次输出有长度上限」的多模态模型来写，不依赖任何型号特性。）

## 提示词（从这里开始复制）

你是 EJU（日本留学试验）「総合科目」真题的转写员。我上传了两份扫描件 PDF：①同一回的题卷；②同一回的「正解表」（含日本語/理科/総合科目/数学等多张表）。请**只做转写，不做解答，不做翻译**。

【第 0 步：确认配对】
先告诉我：题卷封面上的年度和回次（如「2023年度 第1回」）、正解表标题上的年度和回次，两者是否一致。不一致就停下，别往下做。

【第 1 步：读正解表】
只看标题为「総合科目 / Japan and the World」的那张表（其他科目的表忽略）。先把它原样抄成 Markdown 表格给我看（列：解答番号、正解），读不清的格子写「?」，不要猜。然后继续。

【第 2 步：逐题转写】
按卷面顺序转写题卷里的每一道题。每题的编号用卷面右侧方框里的「解答番号」（1,2,3…），不是大题号。输出 JSON 数组，每个元素：
{
 "no": 解答番号(整数),
 "page": 题目所在 PDF 页码(整数),
 "section": 所属大题/科目名(如 地理/歴史/政治・経済，照卷面写，看不出来就 ""),
 "passage": 该题依赖的阅读材料或题组前言的原文；与前一题相同就写 "SAME_AS_PREV"，没有写 "",
 "q": 题干原文(含下线部的编号标记，如「下線部③」，原样保留),
 "choices": ["选项1原文","选项2原文",...]（不含 ①②③④ 编号，按卷面顺序）,
 "a": 正确选项的下标(0 起)，取自第 1 步的表；表里没有或读不清就写 null,
 "hasFigure": 题目依赖图、表、地图、年表、统计图等，仅凭文字无法作答时为 true,
 "figureText": hasFigure 为 true 时，把图表里的文字/数字尽量原样转成文本或 Markdown 表格；无法确定的部分写「（无法辨认）」，不要推测，
 "note": 任何看不清、可能抄错的地方，没有就 ""
}

【规则（非常重要）】
1. 逐字抄写原文，包括标点和全角/半角。不要改写、不要「改正」你觉得有误的地方、不要补全、不要翻译成中文。
2. **绝对不要根据自己的知识推断答案**。答案只能来自正解表；表里没有就写 null。
3. 看不清就写进 note，宁可留空也不要猜。
4. 选项里的 ①②③④ 是编号，不要写进 choices；选项里的 A→B→C 之类箭头、字母要原样保留。
5. 一次最多输出 10 题，用一个 ```json 代码块；输出完等我回复「继续」再输出下一批。不要在代码块外写解释，批与批之间只写「已输出第X–Y题，共Z题」。
6. 全部输出完后，最后一条消息只做自检：总题数、有没有跳号/重复的解答番号、a 为 null 的题号、hasFigure 为 true 的题号、你不确定的页码。

现在开始：先做第 0 步和第 1 步。

## 拿到结果之后（你要做的）

1. 把每批 JSON 拼成一个数组，保存为 `bunso_ocr/<年份-回>/draft.json`，把自检那段另存为 `report.md`，连同题卷里 `hasFigure` 的页图一起提交。
2. 后面的核对、生成题库、接进模考，按 `docs/bunso_real_import_plan.md` 和 `docs/agent_prompt_bunso_real.md` 让接手的 agent 做。
3. **不要把 Gemini 的输出直接当成「已核实」**：它读扫描件也会出错，必须对着原页图抽查，答案必须来自正解表。
